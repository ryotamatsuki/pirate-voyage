# 機能を維持する画面改修の引き継ぎ

作成日：2026年10月1日（日本時間）。
対象：ゲーム版 v0.1.3。
状態：改修用の提案。
以下の改修作業はすべて未実装。

## 1 目指す画面と守る機能

「潮路を調べる船長の航海手帳」を共通の方向にする。
航海中は世界を見て判断し、港では作業を選び、航海帳では得た知識を読む。
同じ暗い枠を全画面で使う代わりに、場面ごとの明るさと情報の並びで役割を示す。

変更するのは配色、書体、余白、枠、配置、既存情報の読み順と短い説明である。
既存の値、状態、操作結果、保存形式を維持する。
デザインの都合で、新しい手順を必須にしたり、選択を自動確定したりしない。

| 維持するもの | 改修時の制約 |
| --- | --- |
| 資金、食料、船体HP、船倉 | 値と単位を保つ。食料とHPを世界観のために隠さない |
| 手動、自動、帆、舵、倍率、目的地 | 既存の操作を使える状態で残す。倍率と航海時間の処理を変えない |
| カメラ、音、一時停止、全画面、ヘルプ | 入口と状態を読める形で残す。初期視点や既定の音設定を変えない |
| 木材の売買、数量、見積り、配送 | 計算、価格、報酬、成立条件を変えない |
| 補給、修理、待機、船の改造、救助 | 費用、適用条件、確認の手順を維持する |
| 発見、目印、接近、観測、報告 | 状態を混ぜない。見た目の強調で未発見情報を開示しない |
| ガイド | 進行、停止、再開、スキップ、保存、旧記録の扱いを維持する |
| ブラウザ保存、JSON、復帰 | 操作を残す。画面の整理でデータ移行を発生させない |
| 二版構成 | ゲーム版の改修を自由航海版へ自動的に適用しない |

航路登録と帰路の移動短縮はM4a-3で作る機能であり、v0.1.3のデザイン改修に先行実装しない。
「北の灯」を現在使える目的地、無料の報酬、船の改造条件へ変えない。
船員、釣り、潜水、建設、予報、新しい敵や遭遇は今回の範囲に含めない。

## 2 情報の優先順位

| 場面 | 最初に見る情報 | 次に見る情報 | 詳細として残す情報 |
| --- | --- | --- | --- |
| 航海 | 船、見つけた対象、現在の行き先 | 食料、HP、操船と倍率 | 風、方位、距離、カメラ、メニュー |
| 発見の選択 | 対象と三つの選択肢 | 寄り道と帰還の食料の目安 | 座標、詳しい説明 |
| 観測の結果 | 分かったこと、未確認 | 次の行動、記録への入口 | 観測日と位置 |
| 港 | 港名、選んだ作業、資金 | 数量と見積り、実行ボタン | 在庫、依頼の説明、港の背景 |
| 報告 | 未報告か受理済みか | 条件と現在使える操作 | 受理日、今後の航路登録 |
| 航海帳 | 記録の見出し、三つの情報群 | 観測日、受理状況 | 日誌、保存、JSON、復帰 |
| ガイド | 今回の目的と対象のボタン | 操作が終わったこと、次の説明 | 全体の手引き、再案内 |

詳細を後ろへ置くことと、機能を取り除くことは区別する。
保存やJSONの操作は既存の画面内で区画を分け、読める見出しを付ける。
新しい画面や保存状態を必要とする大きな再構成は、初回の改修では行わない。

## 3 画面別の指示

### 3.1 開始画面

タイトル、再開、新規開始、船長名、保存状態、バックアップと読み込みを維持する。
大きな作品名と短い目的の説明を分け、操作を選ぶ前にゲームの役割が分かるようにする。

説明案は「小船で交易し、浮標を調べ、失われた潮路の手掛かりを集める」である。
この文言は完成版の大目標と現在の遊びをつなぐ案であり、今すぐ五海域や灯台修理が遊べると伝えない。
装飾の英語は作品名の補助に留め、新規開始や再開を日本語で判別できるようにする。

対象の既存要素：`title-screen`、`title-heading`、`captain-name`、`new-game`、`continue-game`、`save-status`、`restore-backup`、`import-file`。

### 3.2 海上画面

画面を「資源」「現在の航海」「世界を見る範囲」「操船」「地図とメニュー」に整理する。
資源は一行または二行にまとめ、数字の幅を揃える。
食料とHPの危険状態は既存の判定を使い、文字と形でも区別する。

PCでは上部に資源と行き先、下部の左右に操船と海図を置き、中央の船と水平線を開ける。
行き先と入港の操作は、同じ航海情報の領域として見つけられるようにする。
風と方位の表示は、独立した大きな枠を増やすより、操船の情報に揃える。

縦画面では上から資源、行き先、海、操船の順に並べ直す。
常時表示の四資源と停止を保ち、メニューやカメラは小さい文字ではなく押せるボタンにする。
帆と舵のタッチ範囲を確保し、既存の海図と操作の入口を残す。

夜の調整は、帆、船体、浮標が海から分かれる輪郭と明度を先に試す。
昼と同じ色にしたり、恐怖演出を追加したりする必要はない。
発見前の浮標へ恒常的な金色の光や画面上の印を出し、視認条件を飛び越えない。

既存の3D形状とカメラ処理を保った状態で、HUDの余白と位置を先に整える。
新しいカメラ挙動が必要になった場合は、機能変更として別に扱う。
構図のために接近点、座標、航海距離を動かさない。

対象の既存要素：`gold-value`、`food-value`、`hp-value`、`cargo-value`、`destination`、`journey-distance`、`journey-eta`、`journey-progress`、`dock-game`、`next-goal`、`sea-clue`、`port`、`starboard`、`sails`、`auto`、`manual`、`pause`、`chart`、`open-map`、`open-log`、`sound`、`fullscreen`。

[配置検討図](figures/sea-layout.png) は優先順位を示す概念図で、実際の寸法や全ボタンの最終仕様ではない。

### 3.3 浮標を見つけたときの選択

まず対象の名前と短い状況を見せ、次に直行、接近、目印の三つを見せる。
座標、図、詳しい会話は、選択肢と費用を読んだ後にも確認できる順序にする。
三つの選択肢を同じ構造にし、行動名、分かること、航海の負担を対応させる。

| 選択 | 最初に読める説明の案 | 維持する結果 |
| --- | --- | --- |
| 港へ直行 | 予定の交易と配送を続ける | 元の目的地へ向かう |
| 浮標に接近 | 近くで調べるために寄り道する | 目的地を浮標へ変える |
| 目印を残す | 海図に残し、後から戻れるようにする | 記録して元の航海を続ける |

寄り道の食料、帰還の目安、予備は現在の見積りをそのまま表示する。
短い説明にまとめても、数字と詳しい内訳が失われないようにする。
三択に唯一の正解があるような色分けをしない。
ガイドが接近を説明している場合の強調と、通常時の選択の自由を区別する。

PCでは選択肢を並べ、短い縦画面では一列にする。
決定と閉じる操作を、図や長い本文の外側で見つけられるようにする。
選択中に時間と食料消費が止まることを既存の状態として分かる表示にする。

対象：`sighting`、`sea-map` と既存の発見選択ボタン群。

### 3.4 観測画面

開始時は、何を観測するかをセナの短い発話と本作のSVGで示す。
確定後は明るい紙面へ移り、結果を三つの見出しで読む。

| 見出し | 維持する内容 | 表示 |
| --- | --- | --- |
| 分かったこと | 浮標の北側に潮の境目がある | 本文として最も強く読む |
| 未確認 | 「北の灯」の所在と潮のつながり | 疑問符と見出し。未訪問の目的地にしない |
| 次の行動 | 松帆港の海図係で報告する | 現在利用できる行動として示す |

情報を読む前に、大きな「獲得」表示や金貨の演出を置かない。
観測では資金や積荷が増えず、知識が得られることを見せる。
「記録を確認」「閉じる」などの既存操作を保ち、閉じても記録を読み返せるようにする。

対象：`observation`、`close-observation` と既存の記録確定、記録確認の操作。

### 3.5 航海帳と保存

観測記録を最初の区画に置き、日誌と保存の区画をその下に続ける。
新しい保存フラグや記録の種類を追加せず、既存の情報を並べ直す。

見出しと閉じる操作はスクロール領域の外、本文はその内側へ置く。
縦画面では「分かったこと」のような日本語見出しを細い固定幅の列に押し込まず、見出しを上、本文を下にする。
内容の幅を優先し、装飾の余白を縮めても文字を小さくしない。

観測日と受理日は一つの状態欄にまとめる。
未報告、受理済み、別の港にいる状態を文字で区別し、報告できない理由をボタンの近くで読めるようにする。
既存の港へ戻る操作を維持し、別の港から報告先へ瞬間移動する機能は作らない。

保存、JSONの書き出しと読み込み、バックアップ、復帰は専用の見出しの下に残す。
観測内容を探すために、それらの操作を先に通り抜ける配置を避ける。
長い日誌が流れても残る観測記録と、直近の出来事を示す日誌を見た目でも区別する。

対象：`observation-book`、`book-report`、`book-report-note`、`journal-list` と保存、JSON、復帰の既存操作。
[配置検討図](figures/observation-book.png) を参照する。

### 3.6 港と交易

港名、説明、現在の資金を見出しの付近で読めるようにする。
市場、補給、造船、海図係、出港の五つのタブを維持する。
選択中は色に加えて下線や形でも区別し、短い横画面では折り返して押せる幅を保つ。

市場は、商品名と在庫、数量、合計見積り、購入と売却の順に整理する。
配送は同じ市場内でも取引とは別の区画にし、受注、完了、報酬を混ぜない。
表示済みの合計額で決済する現在の処理を維持し、購入と売却の区別を明確にする。

補給、修理、改造は、費用と実行条件を操作の近くに置く。
改造前後の既存性能を読みやすくすることはできるが、段階3以降の船をこの改修で追加しない。
使えない操作は薄くするだけでなく、現在の条件を短く示す。

港の色は暖かい小さな差を使い、取引の数字を背景の絵や模様に埋めない。
大きな画像によってスクロールが増える場合は、背景の装飾を先に減らす。

対象：`harbor`、`port-name`、`close-port`、`port-wallet`、`trade-quantity`、`buy-quote`、`buy-wood`、`sell-quote`、`sell-wood`、`trade-preview`、`delivery-job`、`food-one`、`food-full`、`repair-ship`、`upgrade-ship` と既存の五タブ。

### 3.7 海図係と報告受理

報告前は、現在の観測状態、報告先、操作を一つの領域へまとめる。
受理後は「受理済み」と受理日、満たした二条件を一つの要約として読む。
無効な報告ボタン、完了の説明、同じ条件の一覧を何度も大きく繰り返さない。

航路登録は未実装なので、現在の操作と同じ金色の大きなボタンに見せない。
表示案は「観測と報告がそろいました。登録航路は準備中です」である。
版番号や次のプログラム更新の説明を前面に出すより、今できることを先に示す。

木材の売却、配送、補給、帰港の案内は、現在の資源と依頼に応じた既存の内容を使う。
済んだ配送を再び案内したり、受理後の再報告に報酬があるように見せたりしない。

対象：`report-heading`、`report-speech`、`report-status`、`report-observed`、`report-accepted`、`submit-observation`、`report-result`、`report-book`。

### 3.8 ガイドと手引き

一回の発話は「目的」と「今の操作」を中心にし、実際のボタンを枠と矢印で示す。
詳しい説明は読める区画に残し、短くしたことによって基本の作業が学べなくならないようにする。
実際の数値、ボタン名、完了状態を使い、固定した見本文で案内を進めない。

案内カードが対象を覆う場合はカードの位置を変え、既存の対象へ移動する操作も保つ。
小型画面では、案内文と進む、閉じるの操作を分け、文章のスクロール中も終了できるようにする。
回転時にはカードと矢印の配置を再評価し、横画面で対象の外へずれた印を残さない。

案内の途中で閉じる、続きから読む、完了後に読み返す動作を維持する。
説明中の停止、航海を待つ手順、旧記録での案内は現在の処理に従う。
常時点滅する矢印や、押せるまで待たせる演出は追加しない。

対象：`voyage-guide`、`guide-heading`、`guide-speech`、`guide-task`、`guide-next`、`guide-skip`、`guide-focus`、`guide-recenter`、`guide-scroll-hint`、`help`、`close-help`。

## 4 文字、配色、寸法

実装用の提案値は [design-tokens.json](design-tokens.json) に保存する。
値は比較を始める基準であり、受入条件を確認する前に確定値とは扱わない。

| 要素 | 提案 |
| --- | --- |
| 日本語本文 | システムのゴシック体、16px、行高1.65 |
| 補足 | 14px。必須の操作説明を飾り用の12pxへ下げない |
| 見出し | システムの明朝体、24〜30px。本文と操作はゴシック体 |
| 数値 | tabular-nums。資金、食料、HP、船倉、単位を対応させる |
| 余白 | 4、8、12、16、24、32pxを共通の段階にする |
| 操作の高さ | 本作の目標は44CSS px以上。幅と間隔も確認する |
| 枠 | 操作、選択、情報の境界に限定。すべてを金色にしない |
| 動き | 短い状態変化。操作を待たせず、動きを減らす設定に従う |
| 外部依存 | 外部フォントと外部画像を必須にしない |

| 色の役割 | 値 | 使い方 |
| --- | --- | --- |
| 海上パネル | #112C38 | 資源と操船の背景 |
| 紙面 | #F3EBDC | 観測結果と航海帳 |
| 紙面の本文 | #20343A | 長い日本語本文 |
| 紙面の補足 | #53676B | 日付、補足、未確認の説明 |
| パネルの本文と補足 | #F3EBDC、#B7C9CC | 海上のラベルと数値 |
| 主な操作 | #E8C98D / #182C32 | 金色の面に暗い文字 |
| その他の操作 | #1E5360 / #F3EBDC | 青緑の面に明るい文字 |
| 成功、注意、危険 | #336759、#8B5623、#9D3F3B | 紙面上。状態名と記号を併用 |
| 境界 | #7A969A | 暗い面上の操作境界 |

不透明な組み合わせの計算結果は [確認記録](verification.md) に残す。
文字の4.5:1などの基準はW3Cを参照する。
44pxは本作の目標であり、WCAG 2.2のTarget Size (Minimum)の24CSS pxと同じ値ではない。
[S24](sources.md#s24) [S25](sources.md#s25)

透明なパネルの下には海と空が動くため、色の組だけで実画面の読みやすさを保証しない。
明るい昼、暗い夜、白い波、ガイドの強調中に実際の合成後の表示を確認する。
金色の文字を明るい紙面に置く組み合わせは、この案の検証済み組み合わせに含めない。

## 5 PC、縦画面、横画面

幅だけで分類せず、高さと実際の文字量も使う。
短い横画面では二列を使ってよいが、対象と終了操作を隠さない。
375px幅へすべてを縮小せず、カードや本文の列数を減らす。

| 確認する表示 | 主な確認 |
| --- | --- |
| 1360×900 | 船と浮標の視界、四資源、操船と海図、目的地 |
| 390×844 | 日本語本文の幅、港の五タブ、ガイドの対象 |
| 375×667 | 本文と終了操作、案内と操船の重なり |
| 844×390、701×393、667×375 | 短い高さでの終了操作、タッチ操舵、図と本文 |
| 縦横の回転 | 開いている画面、選択状態、ガイドの対象とフォーカス |
| 200%の文字表示 | ラベルの欠落、横スクロール、操作への到達 |

上記は改修後に確認する条件で、今回すべてに合格したという記録ではない。
倍率の変更はブラウザの表示とゲーム内の1・2・4倍速を区別する。
モーダル内の本文をスクロールさせ、見出し、閉じる、主な操作の位置を安定させる。
固定要素の積み上げだけで解決せず、短い高さでは本文へ使える領域を確保する。

## 6 改修の作業順

| ID | 作業 | 成果と確認 | 状態 |
| --- | --- | --- | --- |
| D0 | 参考作品と現行画面の調査 | 本資料、出典、画像台帳、配置図を保存 | 完了 |
| D1 | 文字、色、余白、ボタンの基礎 | 共通CSSの値と状態を揃える。長文と数値を確認 | 未着手 |
| D2 | 海上の配置と視認性 | PCと縦横画面で船、浮標、資源、操船を比較 | 未着手 |
| D3 | 港、発見、観測、航海帳 | 取引の数字、三択、三つの情報群、受理状態を確認 | 未着手 |
| D4 | ガイドと全体の確認 | 案内対象、キーボード、タッチ、回転、保存、通し操作 | 未着手 |

D1からD4は機能を維持するデザイン改修の作業案で、M4aの子工程を追加完了するものではない。
最初は既存のHTML構造とCSSの調整を中心にし、ゲーム処理の改変を避ける。
同じ関数に画面更新と保存が混在する部分を変更する場合は、状態が同じかを既存テストで確認する。
装飾だけの変更を検証するために、実装をそのままなぞるテストを大量に増やさない。

## 7 改修を完了する条件

| ID | 条件 | 残す証拠 |
| --- | --- | --- |
| V01 | 海上、港、航海帳を見た目で区別できる | 同じ進行状態の前後画像 |
| V02 | 四資源と主要操作が、対象の視界と両立する | PC、縦、短い横画面 |
