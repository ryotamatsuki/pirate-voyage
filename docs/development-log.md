# 開発の判断と変更記録

実装済みの範囲は [開発タスクと進捗](development-status.md)、今後の順序は [一航海の試作の開発工程](voyage-prototype-plan.md) を参照する。
ここには、何を変えるか、なぜ変えるか、何を確認したかを記録する。

## 2026年9月30日 M4a-1を実装（画面確認中）

対象は [Issue #2](https://github.com/ryotamatsuki/pirate-voyage/issues/2)。ゲーム版をv0.1.2へ更新した。浮標の恒久IDと位置、海鳥、海図の未探索セル、セナによる直行・接近・目印、元の針路への復帰、寄り道と帰港の食料見積りを追加した。浮標への接近では船を停止し、任意に港へ戻れる。目的地を変えても配送と通常の積荷は維持する。

理由は、港へ向かう途中で手掛かりに気付き、食料と予定を見て進路を選べるようにするため。タイマーで発見を出さず、浮標から45ゲーム海里以内の位置で一度だけ視認する。初期の標準航路では1倍の固定刻みで約13秒に見える配置とした。初期船を強制的に襲撃・損傷させない。視認・目印・接近は観測済みや報告済みにせず、報酬も出さない。

保存はschema 1 / two-ports-1を維持し、任意のexploration.version 1を追加した。旧記録の資源・依頼・改造・案内を保持し、発見は未取得の状態から始める。海図は64ゲーム海里のチャンク、8×8セル、16桁の16進文字列を負座標込みで保存する。救助で航路は解除するが、発見と目印は残す。不正なID・形式・版は読み込み前に拒否する。

確認：node --test tests/*.test.cjs の33項目に成功。従来の22項目と探索の11項目で、通過・接近・手動・針路変更後の復帰、配送と交易、見積りと実消費、往復の食料、再読込み、旧記録、不正入力を確認した。三つの埋め込みスクリプトの構文も確認した。画面確認のため、同じゲームをiframeの幅変更で表示する開発用ページを追加した。PC幅とスマートフォン幅の実操作・表示確認は公開先で進める。初見の三問、実機Safari、性能測定は未実施。

自由航海版のindex.htmlと仕様書版1.2のMarkdown・Wordは変更しない。今回の変更は既存仕様の子工程の実装で、完了範囲は開発進捗へ記録する。M4a全体のクローズはM4a-2、M4a-3、通し確認と初見の三問の後。

## 2026年9月30日 一航海の試作を優先する方針を採用

利用者から、航海が到着まで待つ場面になっているという指摘を受けた。
海洋ゲームと自由探索を扱う八作品の公開一次資料を比較し、発見が次の目的を生むこと、知識で航海を改善すること、調査済み航路を快適に再利用することを採用した。
根拠は [調査提案書](exploration-research_2026-09-30.md) に記録した。

開発順を、一航海の試作、五港への拡張、予報と十遭遇、第一章の順に変更する。
一航海の試作には、観測浮標の発見、寄り道、観測、報告、航路登録、帰路の移動短縮を含める。
M0からM3と初回ガイドは完了済みのまま保持する。

試遊では「何を見つけたか」「なぜ進路を変えたか」「帰港後に次は何をしたいか」を記録する。
移動時間だけで面白さを判断せず、対象への気付きと選んだ理由、その後の目的を確認する。
初見の試遊はまだ実施していない。

今回の成果は、開発工程、Issue、受入項目、試遊ひな形、調査資料の保存と仕様書版1.2への反映である。
ゲーム版の実装基準はv0.1.1、コミット `419152009b712658b7d4aaf1fa208d7e2a49e6fa` とする。
この文書更新ではゲームのHTMLとテストを変更しない。

文書の確認：Markdownの参照、工程ID、状態、受入項目の対応を確認する。
Word版は24ページへ描画し、全ページを確認した。
文書を保存するコミットと各作業のIssueはGitHubの履歴から参照できる。

## 以後の記録方法

実装または仕様変更の単位ごとに、日付、工程ID、Issue、具体的な変更、変更理由、確認結果、保存への影響、未解決事項を記録する。
試遊の結果は対象のコミットと条件を残し、対応する改善のコミットへ結び付ける。
ゲームを公開した場合は版とURL、自由航海版の保持も記録する。
